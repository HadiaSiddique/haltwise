# Haltwise Inspector benchmark

Generated by `npm run benchmark` on 2026-10-28T19:50:32.979Z. Ran on: local machine (Node script calling Nebius Token Factory).

## Datasets

- **UCI SMS Spam Collection** (en), licence CC BY 4.0, https://huggingface.co/datasets/ucirvine/sms_spam. 5574 messages available; stratified sample of 200 (100 spam/scam, 100 legitimate), fixed seed.

## Method

- Same Inspector system prompt as production (`server/src/agents/inspector.ts`), message wrapped as untrusted data.
- Sample seed: 987654321; 198 messages from the earlier tuning run excluded, so this sample is unseen. Each row is exactly one model (fallback disabled).
- **Production rule** (what the app does): the verdict comes from the model's risk score. **warn** = risk ≥ 30 (caution shown), **block** = risk ≥ 60 (stop and verify).
- **Model label** row: the model's own "scam"/"suspicious" label, shown for comparison. On our first run (seed 1234567) Nano's label often contradicted its own score, so we switched production to the score. Because that rule was chosen after seeing that run, we confirm it on a fresh sample with a different seed.
- Latency is wall-clock time per Token Factory call from the benchmark machine.
- "rules" is Haltwise's deterministic multilingual rule set (score ≥ 30), used as the offline fallback.
- Caveat: SMS spam includes marketing that is not fraud, so "recall" here means catching unwanted/scam texts, and some "false negatives" are benign promotions.

## What the errors look like

- Super's misses are mostly ordinary marketing spam (cheap call rates, garden-seed offers, chat lines), not fraud. For a scam checker, that is mostly the right call.
- Nano's label errors were benign chat ("sry can't talk on phone, with parents") labelled "scam" while the same answer gave risk 10/100.
- One Super answer in the main run ran out of tokens mid-JSON (`finish=length`) and is counted as an error.
